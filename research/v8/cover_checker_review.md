# V8 fractional-cover checker and optimizer review

This is a read-only audit of `experiments/v8_fractional_cover.py` and
`tests/test_v8_fractional_cover.py`. The focused test command actually ran:

```text
python3 -m unittest tests.test_v8_fractional_cover -v
Ran 7 tests ... OK
```

The passing tests establish executable behavior for the tested cases. They do
not establish optimizer convergence, a universal partition comparison, or
method-learning performance.

## Mathematical soundness

The checker is sound for the stated certificate form. It parses the operator
through `clean`, reconstructs every coefficient by exact `Fraction` addition,
checks each pair in every group with `_anti`, checks each group's nonnegative
`upper` and `upper² >= sum(coefficients²)`, and requires the claimed total to
equal the sum of those uppers. It does not trust optimizer metadata, the
reported objective trace, group statistics, or method names. Re-running
`check_fractional_cover(op, witness)` is sufficient to validate the submitted
witness independently of how it was proposed.

The root check is conservative: `_sqrt_interval` produces an upward rational
bound, and the checker only accepts an upper whose square encloses the exact
rational sum of squares. Exact reconstruction also means float rounding in
the proposal cannot create a false certificate; `rationalized()` reconciles
each coefficient and the checker verifies the result.

The coordinate update has the intended local argument. Holding all other
entries fixed, group `j` contributes `sqrt(a_j²+x_j²)`, where `a_j` is the
norm of the other entries. For a shared coefficient with fixed sum, the
stationary condition gives `x_j` proportional to `a_j` (with a common sign),
which is the implemented `vals[p] * a_j / sum(a)`. This is a coordinate
minimizer when `sum(a) > 0`; zero-`a` degeneracies are left unchanged rather
than asserted to improve. The implementation records a trace but never uses
it for acceptance. Thus this is a bounded heuristic with exact post-checking,
not a proof of global optimality or convergence.

## Fail-closed parsing and resource caps

The checker rejects wrong schemas, missing keys, unknown terms, empty groups,
zero incidences, non-anticommuting pairs, duplicate incidence through failed
reconstruction, negative or too-small roots, and claimed-bound mismatches.
`proof_fraction` caps rational text length and integer bit length. The cover
caps are 512 terms, 2,048 incidences, and (after the partition-compatibility correction) 512 checker groups; the proposer family remains capped at 128 groups; pair checks are bounded
by those incidences. The focused malformed-input tests cover these paths.

One residual review limitation is that `check_fractional_cover` does not add
its own explicit cap on the number of characters in arbitrary dictionary keys
before membership lookup; the operator path caps Pauli labels through `clean`,
and witness labels must be members of that cleaned operator, so the effective
label length is bounded by the input operator. The rational parser's existing
5,002-character and 8,192-bit limits cover coefficient and root text.

The checker catches the listed parsing exceptions and returns `rejected`.
Unexpected exceptions from dependencies would still escape, so a production
boundary should treat any checker exception as rejection and enforce an outer
wall-clock/memory limit. That is an operational hardening recommendation, not
a demonstrated false acceptance in this implementation.

## C5 claim and fairness of comparison

For the supplied C5 graph with unit coefficients, a disjoint partition can
contain at most two edges; the remaining vertex is a singleton. Therefore its
best partition cost is exactly `1 + 2*sqrt(2)`. The five-edge fractional cover
with half coefficient on each incidence has five group costs `sqrt(1/2)`, for
`5/sqrt(2)`, which is strictly smaller. This is a fair analytic comparison
against every *disjoint partition* of that graph, not merely against the two
partitions generated by the code.

The test named `test_odd_cycle_strictly_beats_every_partition` does not itself
enumerate every partition. Its supplied-edge arm validates the claimed C5
cover and compares against the analytic constant; its generated arm only
checks that the default family also finds a result below that constant. The
comment's “every partition” conclusion is justified by the C5 combinatorics,
but the test would be clearer if the analytic partition bound were stated as
a separately tested helper or proof fixture. No issue was found with the
numeric inequality.

The full-clique test is also fair for the supplied three pair groups: the
proposer explicitly retains the ordinary full three-Pauli clique, achieving
`sqrt(3)`. Splitting uniformly over only the three edges gives `3/sqrt(2)`,
which is worse; the baseline fallback is what makes this comparison fair. It does not show that the optimizer finds the global best
cover over arbitrary group families.

## Performance and method-claim boundary

The proposer is bounded (`iterations <= 128`, fixed group/incidence caps) and
retains conventional partition candidates, so optimization cannot invalidate
certificate soundness. However, the implementation does not prove that the
coordinate objective is monotone after rationalization, nor that its selected
cover is globally best. It can spend substantial exact checking work after a
cheap float proposal; those costs must be charged in any proposer-performance
comparison. `construction_seconds`, pair counts, and the internal checker
receipt are useful accounting fields, but they are self-reported by the
proposer and cannot replace an evaluator-side cost ledger.

Most importantly, the tests demonstrate a valid fractional-cover witness and
the C5 separation from disjoint partitions. They do not demonstrate that this
is a learned scientific algorithm, that it beats every strong baseline on a
held-out family, or that it improves a second acquisition after amortizing
discovery and verification. Those claims require the V8 causal controls,
same-checker evidence, prospective holdouts, and full-cost accounting.
